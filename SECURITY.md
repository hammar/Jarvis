# Security reporting policy

Jarvis is experimental and incomplete. There are no supported releases or
guaranteed security updates, response times or bounty payments. Do not use
it for safety-critical operations or expose it to the public internet.

## Reporting a concern

When GitHub private vulnerability reporting is available, use the
repository's **Security** tab and **Report a vulnerability** control.
Provide the affected revision, a minimal reproduction using synthetic data,
expected behavior and observed behavior.

If that control is unavailable, do not post vulnerability details publicly.
You may open an issue requesting a private reporting channel, without any
reproduction, exploit details or sensitive information, and wait for a
private channel before sharing details. Availability of a private channel
and a response is not guaranteed.

Never include credentials, private prompts or conversations, household
information, real device identifiers or unredacted logs in public issues
or pull requests. Use controlled fixtures rather than real devices or
private data in a reproduction. This policy does not authorize testing
against anyone's household, infrastructure or deployed services.
